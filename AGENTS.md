# ConsistenCy repository guidance

## Project contract

- Treat ConsistenCy as evidence-driven review infrastructure: deterministic analysis runs first; an LLM is an optional explanation and synthesis layer.
- Keep the TypeScript API responsible for orchestration, persistence, provider calls, and publication. Keep the Python engine deterministic and JSON-over-stdio compatible.
- Treat risk scores as triage signals, not defect ground truth. Ground conclusions in file paths, findings, signal breakdowns, and confidence.

## Runtime and setup

- Use Node.js 22.x and Python 3.12 for baseline verification.
- On Windows, prefer `.\.venv\Scripts\python.exe`; if it is unavailable, use `py -3.12` only after `--version` confirms Python 3.12.x.
- On Unix, use `python3.12` or an activated virtual-environment interpreter only after `--version` confirms Python 3.12.x.
- Install JavaScript dependencies with `npm ci`.
- On Windows, install Python dependencies with `.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt`; on Unix, use the verified Python 3.12 interpreter.
- Copy `.env.example` to `.env` only for local configuration. Never commit `.env`, tokens, private keys, generated workspaces, or local databases.

## Repository map

- `apps/api`: TypeScript HTTP API, workers, configuration, GitHub integration, Notebook orchestration, and LLM providers.
- `apps/web`: React/Vite Web UI.
- `packages/schema`: shared TypeScript schemas and protocol types.
- `engine`: deterministic Python analyzers and JSON-over-stdio protocol.
- `tests` and `apps/**/**.test.*`: Python, TypeScript, and end-to-end tests.
- `docs`: public architecture, API, Notebook, security, and setup documentation.

## Working rules

- Preserve unrelated user changes in the worktree.
- Prefer the shared schemas over parallel ad hoc request or response types.
- Preserve the public-PR boundary: read-only analysis must not publish comments, apply patches, execute repository code, or silently broaden GitHub permissions.
- Keep secrets server-side. Do not expose provider keys, GitHub credentials, bearer tokens, Authorization headers, or local absolute paths in Web UI payloads, logs, screenshots, or fixtures.
- Never execute Python, JavaScript, shell, or patches generated by an LLM merely to perform analysis. Analyze source as data.
- When `confidence` is `0`, a finding has no line number, or no baseline is available, treat the output only as a manual-review lead, not as verified evidence of a defect.
- For deterministic local analysis from Codex, use `$consistency-review`. For direct Windows invocation, run `.\.venv\Scripts\python.exe .agents\skills\consistency-review\scripts\analyze_repo.py` with repository-local paths; on Unix, use a verified Python 3.12 interpreter.

## Verification

- Start with the smallest tests that cover the changed behavior.
- Before calling a change baseline-verified, run the applicable checks under Node.js 22.x and Python 3.12.
- Full checks are documented in `README.md`; common commands are:
  - `npm run verify:runtime`
  - `npm run verify:docs`
  - `npm run typecheck`
  - `npm test`
  - `npm run build`
  - `.\.venv\Scripts\python.exe -m ruff check engine tests evaluation/scripts examples` (Windows; substitute the verified Python 3.12 interpreter on Unix)
  - `.\.venv\Scripts\python.exe -m pytest -q` (Windows; substitute the verified Python 3.12 interpreter on Unix)
  - `npm run test:e2e`
