# ConsistenCy repository guidance

## Project contract

- Treat ConsistenCy as a repository-native Agent Harness for evidence-grounded review: Kernel capability security, Cordis reactive harness, and deterministic Evidence Engine.
- Keep the TypeScript API responsible for HTTP, persistence, and workload runtime. Keep the Python engine deterministic and JSON-over-stdio compatible.
- Treat risk scores as triage signals grounded in file paths, findings, signal breakdowns, and confidence.
- ConsistenCy product runtimes are real-data and real-LLM only (DeepSeek, OpenAI, or Anthropic via the bundled Pi runtime); there is no user-facing demo or mock runtime mode.
- CI and isolated unit tests may use an internal `LLM_PROVIDER=mock` / `MockLLMProvider` double for deterministic orchestration checks. That double is never exposed as a product runtime setting.
- This project is terminal-first. The terminal entry point is `consistency review` (`apps/cli`); `apps/api` is a headless HTTP, persistence, and workload layer. There is no bundled graphical interface.

## Runtime and setup

- Use Node.js 22.x (`>=22.19.0 <23`) and Python 3.12.x for baseline verification; `scripts/baseline-runtime.mjs` enforces both.
- On Windows, prefer `.\.venv\Scripts\python.exe`; if it is unavailable, use `py -3.12` only after `--version` confirms Python 3.12.x.
- On Unix, use `python3.12` or an activated virtual-environment interpreter only after `--version` confirms Python 3.12.x.
- Install JavaScript dependencies with `npm ci`.
- On Windows, install Python dependencies with `.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt`; on Unix, use the verified Python 3.12 interpreter.
- Copy `.env.example` to `.env` only for local configuration. Never commit `.env`, tokens, private keys, generated workspaces, or local databases. Settings and encrypted secrets live under `.consistency/`, which is gitignored.

## Repository map

- `apps/api`: TypeScript HTTP API, SQLite store, workload runtime, workers, GitHub integration, and the notebook graph.
- `apps/cli`: terminal entry point (`consistency review`), argument parsing, terminal renderer, exit-code contract, and CLI-side configuration resolution.
- `packages/kernel`: CapabilityBroker, SyscallGateway, KernelScheduler, ContextVM, AgentControlBlock, AuditJournal.
- `packages/harness-core`: Cordis Fiber runtime, Coeffects, and CapabilityLifecycleAdapter.
- `packages/workload-review`: ReviewWorkload, Supervisor Planner, and specialized review agents.
- `packages/repository`: RepositorySnapshot pinning and Git repository adapter.
- `packages/vcs-core`: VCS types, git status, and commit tracking.
- `packages/schema`: shared TypeScript schemas and protocol types.
- `packages/plugins-builtin`: Tree-sitter AST queries, secret detectors, and deterministic analyzers.
- `engine`: deterministic Python analyzers and JSON-over-stdio protocol.
- `tests` and `apps/**/**.test.*`: Python and TypeScript tests.
- `evaluation` and `engine/evaluation`: scoring datasets, metrics, and rule-evaluation code.
- `docs`: canonical architecture, security, repository workspace, review runtime, and configuration documentation.

## Working rules

- Preserve unrelated user changes in the worktree.
- Prefer shared schemas over parallel ad hoc request or response types.
- Preserve the public-PR boundary: read-only analysis must not publish comments, apply patches, execute repository code, or silently broaden GitHub permissions.
- Keep secrets server-side. Do not expose provider keys, GitHub credentials, bearer tokens, Authorization headers, or local absolute paths in model-visible payloads, logs, screenshots, or fixtures.
- Never execute Python, JavaScript, shell, or patches generated by an LLM merely to perform analysis. Analyze source as data.
- Keep the honesty rules of the terminal report: what a run could not check must stay more prominent than what it did check, and a degraded run must never render like a clean one.
- For deterministic local analysis from Codex, use `$consistency-review`. For direct Windows invocation, run `.\.venv\Scripts\python.exe .agents\skills\consistency-review\scripts\analyze_repo.py` with repository-local paths.

## Verification

- Start with the smallest tests that cover the changed behavior.
- Before calling a change baseline-verified, run the applicable checks under Node.js 22.x and Python 3.12:
  - `npm run verify:runtime`
  - `npm run verify:docs`
  - `npm run typecheck`
  - `npm test`
  - `npm run build`
  - `.\.venv\Scripts\python.exe -m pytest -q`
- `npm run verify` runs exactly that sequence (plus `audit:deps`) as one command.
